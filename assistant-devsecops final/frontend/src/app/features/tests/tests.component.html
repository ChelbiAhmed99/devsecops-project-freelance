Brique 2

Tests automatisés

Résultats des tests du projet, couverture de code, tests instables et lien avec les erreurs de logs.

Comment fonctionne cet écran ?

Cet écran n'écrit pas de tests : il récupère les résultats des tests existants du projet, les conserve dans un historique et les analyse. Les résultats peuvent arriver de trois façons :

  1. Lancer les tests — le serveur exécute mvn test sur le projet analysé, puis lit les rapports produits (target/surefire-reports) et la couverture JaCoCo. Durée : 1 à 3 min.
  2. Importer des rapports (bas de page) — vous déposez les fichiers TEST-*.xml produits ailleurs (poste de développement, autre projet Java, Jest, pytest, Cypress…). Aucun outil requis sur le serveur.
  3. Pipeline CI/CD — à chaque build, le pipeline publie ses rapports sur POST /api/ci/tests. C'est le mode normal en équipe : l'historique se remplit tout seul.

Chaque arrivée crée une exécution numérotée (#1, #2…). L'écran affiche la dernière ; cliquez sur un numéro sous la courbe pour consulter une exécution plus ancienne.
