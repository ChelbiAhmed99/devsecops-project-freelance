Applications

Chaque application a ses propres résultats de tests, logs (applicatifs, serveur, CI), vulnérabilités, validations et rapports. Les données publiées sans code d'application sont rattachées à l'application par défaut.

Comment rattacher les données à une application ?

Pipeline CI/CD : ajoutez le paramètre app=<code> aux appels /api/ci/tests, /api/ci/logs, /api/ci/security/… et /api/ci/quality-gate. Pour les logs, logType=SERVER (JBoss/WildFly) ou logType=CICD précise la couche ; sinon elle est déduite.

Sources de logs : les logs dont la source figure dans la liste déclarée sont automatiquement rattachés à l'application.

Criticité : elle adapte la politique de validation (seuils plus stricts et revue humaine systématique pour une application critique). Les surcharges (JSON) permettent d'ajuster finement la politique, par exemple {{ '{' }}"minCoverage": 70, "weights": {{ '{' }}"SECURITY": 40{{ '}' }}{{ '}' }}.
